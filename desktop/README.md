# AiTok 桌面助手

支持 macOS（Apple Silicon / Intel）与 Windows x64。应用内置 Electron / Node 运行环境，使用电脑上安装的 Chrome 或 Edge，复用项目现有 Session、SOCKS5、账号助手与操作记录功能。

## 0.0.5

- 账号助手新增「更新 Session」，读取当前登录会话、校验账号并加密保存到后台。
- 邮箱及套餐下方同步显示账号备注，支持换行和长文本滚动。
- 登录校验遵循系统代理，主进程独立重连，支持快速重试、唤醒后校验及「立即重试」。
- 桌面端与账号助手版本统一为 0.0.5；Session 保存及备注读取需配套更新后端。

## 0.0.4

- 账号页顶部支持「打开空白浏览器」：在已授权登录的助手中选择已保存 SOCKS5 代理，打开独立的 `about:blank` 窗口手动登录。无需已有账号或 Session，不加载账号小助手，不自动导入登录结果；窗口资料独立保存，关闭窗口不删除本机资料。
- 提供测试版和线上版两个安装包，固定连接各自后台，应用标识、配置和加密登录状态独立。
- 点击「授权登录」跳转后台，完成登录并确认后回到助手；登录身份有效期为 24 小时，后台退出登录、修改密码或停用账号会使授权失效。凭证使用系统安全存储加密，界面不接收凭证。未登录不启用账号服务，退出助手登录会关闭账号窗口。
- 登录校验使用 Electron 网络层，遵循系统代理设置，不携带网页登录 Cookie、不缓存校验响应。网络超时或后台暂时不可用时显示具体原因并保留已打开的账号浏览器和加密凭证；首次失败 3 秒后重试，持续失败逐步退避至最多 30 秒，支持「立即重试」。主进程独立执行重连，窗口隐藏后仍有效，电脑唤醒时立即重新校验。恢复前暂停新的账号操作；授权明确失效、到期或主动退出时关闭账号窗口，连接故障不会被当作退出登录。

- 移除助手内临时安全码输入框；未保存安全码时照常填充卡号和地址，在官网手动补填安全码。

- 助手使用独立内嵌文档隔离点击和焦点事件，操作助手不会触发官网弹框的外部点击关闭。
- 已绑定的付款卡、账单地址固定展示；只有未绑定项提供下拉选择，失效绑定须回后台处理。
- 移除切换账单地址、切换下一张卡、刷新银行卡和地址按钮，保留逐项复制、完整复制及手动填充。
- 需要同步更新后端：地址绑定通过事务行锁防止多个账号并发占用同一地址，搜索与随机绑定排除占用地址。

## 0.0.3

- 小助手支持一键复制带字段名称和换行格式的卡号、有效期、安全码及账单地址。
- 优先展示当前账号已绑定的付款卡和账单地址，绑定对象不可用时明确提示。
- 桌面窗口与小助手面板均显示 0.0.3，便于核对已加载的版本。

升级时退出旧助手，覆盖安装新版，再重新打开账号窗口；站点配置、代理及浏览器资料继续保留。

## 安装与使用

- macOS：选择对应 CPU 架构的 DMG，将「AiTok 助手」拖到 Applications，再打开。
- Windows：运行 x64 `.exe` 安装程序，按向导完成安装。
- 测试版固定连接 `http://localhost:15680`（助手端口 `15684`），线上版固定连接 `https://toktopup.com`（助手端口 `15683`）。打开应用后点击「授权登录」，在后台完成登录并确认授权，再返回助手使用。访问 `127.0.0.1` 与 `localhost` 属于不同来源，后台地址须与对应版本一致。
- 后台须同步部署本轮前后端，提供 `/desktop/authorize` 授权页及 `/api/desktop-auth`、`/api/desktop-auth/session` 接口；本次授权功能无需数据库结构迁移。
- 在后台网页点击“打开账号”。若修改助手端口，在网页账号弹窗或 SOCKS5 管理的「本机助手连接」中保存相同端口，可点击“测试连接”。浏览器询问本地网络权限时选择允许。
- 每个账号自动保存独立指纹种子，关闭重开保持不变。关闭账号窗口后可在网页点击「重新随机生成指纹」，下次打开生效，原登录数据保留。不需要 AdsPower 软件或 Local API。
- 关闭窗口后应用继续常驻菜单栏 / 系统托盘；可勾选“开机启动”。从托盘退出会关闭账号浏览器，有打开的账号时先确认。移除站点也需确认，保留本机浏览器与代理数据。

不再需要项目源码、手工运行 Node 或保持终端。默认不启用开机启动，由用户自行选择。应用不自动付款，不降低网站账号权限或绕过 2FA。

## 多环境和端口

测试版和线上版可同时安装、运行，配置与登录状态独立。每个版本仅连接对应后台，使用独立的回环端口与来源校验，不监听局域网。本机端口可按需修改，并须在对应后台网页保存相同端口。

端口已占用时应用不会结束占用进程。首次升级时，退出旧的命令行启动器后再点击“启动”；或者更改双方端口。桌面应用有单实例保护，重复打开仅显示已有窗口。不要让桌面与命令行启动器同时管理同一站点的同一账号目录。

使用回环 HTTP 保留与普通浏览器的通信能力；完全取消此通信端口需要浏览器扩展及 Native Messaging，不属于本版实现。

## 本地开发与打包

构建需要 Node.js 22+。在 `desktop` 目录执行：

```bash
npm ci
npm start
```

```bash
npm test                 # 隔离配置、启停、多站点和持久化测试
npm run test:smoke       # 在有桌面的环境测试真实 Electron 窗口，不使用业务账号
npm run dist:mac -- --arm64 # 一次生成测试版、线上版两个 DMG
npm run dist:mac -- --x64
npm run dist:win -- --x64
```

默认打包测试版和线上版；可加 `--channel=test` 或 `--channel=production` 单独生成一个环境。安装包名称含 `test` / `production`，当前版本号为 0.0.5。

`desktop/dist` 只接收最终安装包：macOS 仅生成 `.dmg`，Windows 生成 `.exe`。不生成 ZIP、DMG 差分更新文件，也不创建 `verified` 目录或额外校验清单。发布打包使用独立临时目录，成功后复制安装包，结束时清理临时目录；不会将解包目录、运行库缓存或调试文件放入 `dist`。当前无自动更新功能。打包失败不会覆盖已有安装包，已有其他版本和平台的安装包保留。

`npm run pack` 仅生成用于调试的解包应用，输出至 `desktop/.pack`；界面测试截图保存在 `.pack/test-artifacts`，这些内容不会进入安装包。

macOS 安装包在 macOS 上构建，Windows 安装包建议在 Windows 上构建。仓库提供手动触发的 GitHub Actions「桌面助手安装包」，在 macOS / Windows 原生 runner 上分别打包并上传 artifacts，不自动发布 Release。修改桌面代码或其引用的浏览器脚本后，已安装版需要重新打包，退出旧助手后替换安装并重启；源码开发使用 `npm start` 会自动重新构建。

默认 CI 产物未签名，macOS 未公证；系统可能拦截或提示未知开发者，尚不能当作已签名的公开发行版。正式分发需配置 Apple Developer 的 Developer ID 签名和公证、Windows 代码签名证书，再按 electron-builder 的签名流程构建；项目不保存证书或密码，也不会自动关闭系统安全校验。

## 数据与边界

- 站点列表：各版本 Electron 用户数据目录中的 `sites-test.json` / `sites-production.json`，通过临时文件原子写入；配置损坏时提示错误并保留原文件，不用默认配置覆盖。站点移除写 `deleted_at`，不删除浏览器或代理文件。
- 代理和浏览器目录：沿用 `~/.aitok/browsers`；Windows 使用当前用户主目录。同站点继续读取原加密代理配置，账号标识和资料目录不变。
- UI 不加载远程网页，使用沙箱、隔离上下文、CSP 和固定 IPC 白名单；后台网站在系统默认浏览器打开。UI 不接收 Session、代理密码或卡号。
- 登录状态：各版本用户数据目录中的 `login-test.json` / `login-production.json`，只保存经系统安全存储加密的专用凭证；不会保存后台密码或复用网页登录令牌。授权回调使用短时随机地址，只监听 127.0.0.1，校验来源和随机状态并仅消费一次。
- 安装包升级前先退出助手。当前版本不包含自动下载更新功能。
